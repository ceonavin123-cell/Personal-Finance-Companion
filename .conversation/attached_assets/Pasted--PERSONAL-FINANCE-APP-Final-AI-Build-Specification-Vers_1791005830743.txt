# PERSONAL FINANCE APP

## Final AI Build Specification

**Version:** 1.0
**Purpose:** Build a production-ready MVP personal finance application.
**Target platforms:** Lovable, Replit, Antigravity, or similar AI coding platforms.

---

# 1. BUILD INSTRUCTION

Build a modern, simple, responsive personal finance web application.

The application must help ordinary users:

* Record income
* Record expenses
* Record loans
* Record grants
* Track money they owe and are owed
* Create budgets
* Create savings goals
* Understand their financial situation
* Learn basic financial concepts

The most important feature is extremely easy transaction entry.

Users should be able to enter transactions using:

1. Voice
2. Text
3. Camera/receipt scan
4. Manual form

The application should NOT feel like accounting software.

It should feel like a simple financial companion.

---

# 2. PRODUCT PRINCIPLE

The main user experience is:

```text
What happened to your money?
```

The user can say:

> I spent 500 on lunch.

or type:

> Salary 85000 today

or scan:

> A restaurant receipt.

The application converts this into a structured transaction and asks the user to confirm it.

# 16. SECURITY

Enable Supabase Row Level Security on all user-owned tables.

Every user-owned table must restrict records using the authenticated user ID.

Conceptually:

```sql
auth.uid() = user_id
```

Users must never be able to access another user's:

* Transactions
* Accounts
* Loans
* Grants
* Goals
* Budgets
* Attachments
* API settings

Use private storage buckets.

When implementing this specification, build the application incrementally.

First create the database and authentication.

Then build the application shell.

Then build transactions and dashboard.

Then implement text input.

Then voice.

Then scanning/OCR.

Then budgets, goals, loans and grants.

Then insights and financial education.

Then integrations.

Do not generate fake financial data in production.

For development, seed clearly marked demo data only.

Do not claim an external API is connected unless the connection has actually been tested.

The finished application must be functional, responsive, secure, and usable without AI/API configuration.

The core manual finance functionality must always work independently.

**Primary success criterion:**

> A new user should be able to open the application and record their first financial transaction in less than 30 seconds without knowing anything about accounting.
